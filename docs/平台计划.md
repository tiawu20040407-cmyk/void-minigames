# VOID 平台计划

> 状态：计划已定（2026-11-25），逐项开发。**第 1、2 步已部署；第 3 步分 3a–3d 进行，3a（仿生人 HUD）、3b（办公电脑）已完成、待部署**。每一项开始写代码前，先和 KP 确认细节。
> 本文是《VOID 外置小游戏 设计计划》的配套文档。小游戏本身的设计看那份；本文只讲把游戏包起来的网站平台。

---

## 一、为什么要做平台

- 现在 `/hack/`、`/footage/` 是公开静态页面，知道网址就能打开，游戏里的剧透（例如录像恢复画面）写在页面代码里，F12 可见。
- 平台的核心：**服务器确认登录和权限后才发送游戏文件和资料**。没有权限的请求返回 404，猜到网址也打不开。
- 平台上线后关闭旧的公开地址。

## 二、整体结构

```
登录页
├─ 访客进入 → 警察厅内网（公开，无剧透）
├─ 注册 → 邀请码 + 角色卡录入 → KP 审核
├─ 玩家登录 → 警察厅内网 + 仿生科终端 + 世界观网站 + 个人档案
│     ├─ 仿生人 PL（HO2、HO4）→ 仿生人界面（HUD）
│     └─ 人类 PL（HO1、HO3）→ 办公电脑界面（Windows 风格）
└─ KP 登录 → KP 控制台
```

搭档关系（模组原文）：HO1 人类 — HO2 新型仿生人；HO3 人类 — HO4 旧型仿生人。

## 三、各部分

### 1. 登录页
- 三个入口：登录、注册、访客进入。KP 入口放在不显眼处（如页脚小字），安全性靠后端。
- 风格：警察厅职员终端登录画面，对应导入里黑田说的“登记完成”。

### 2. 注册（每人一个邀请码）
- KP 在控制台为每个位置生成邀请码，**一次性**，用过即失效。
- 邀请码绑定 HO：用 HO2 的码注册，账号自动为 HO2。
- 注册时填写角色卡，只录游戏要用的项目（2026-11-25 定，完整角色卡仍靠骰娘）：姓名、HO、种类、DEX、HP（上限）、《计算机使用》《艺术（黑客）》《侦查》《机械维修》《开锁》《灵感》。HP 用于 HUD 搭档资料，当前 HP 由 KP 在控制台维护。提交后为“待审核”。KP 审核、修改、锁定后才能进入仿生科终端；审核前登录只能看访客内容。

### 3. KP 登录
- 账号 + 密码 + KP 密令，三项都对才能进入。KP 账号名：咕咕。密码和密令由 KP 本人在服务器上设置，不经过 Claude，不写入仓库。
- 连续输错锁定一段时间；记录登录时间和 IP；会话过期。
- 可选：`/kp` 路径加 Cloudflare Access（邮箱验证码）。

### 4. 访客：警察厅内网
- 内容：公告、出勤表、任务栏（普通职员能看到的内容），以及**模组作者和译者信息页**（作者名、原作链接、翻译说明）。
- 访客为任何知道 VOID 的人，因此这里只放无剧透内容。
- 内容由 KP 在控制台编辑，可随剧情更新（例如 10/24 后出勤表上 HO1 显示“停职”）。
- 访客页面允许 Cloudflare 缓存。

### 5. 仿生人 PL 界面（HO2、HO4）
- 风格：HUD 叠加层，扫描线、数据流。
- **扫描**：KP 预先写扫描条目，开放后玩家点“扫描”查看（细节见第七章第 3 步）。
- **搭档资料**：HO2 看 HO1，HO4 看 HO3。心跳、血压、呼吸、受伤程度由角色卡 HP 换算；KP 改 HP 后实时同步，也可手动覆盖单项数值。
- **游戏入口**：随 KP 解锁出现（见第 7 节）。
- **界面故障**：KP 可触发雪花、错字、短暂黑屏，配合剧情。
- 可选伏笔（KP 决定是否使用）：HO1 体内是 HO2 的心脏。做成一条只对 HO2 的扫描条目，例如“心脏生物识别码与本机登记数据部分吻合”。

### 6. 人类 PL 界面（HO1、HO3）
- 风格：仿 Windows 的办公电脑，有桌面、窗口、文件夹、任务栏。
- 游戏入口为桌面图标或文件夹里的程序，解锁后出现（HO1 梦境组装、HO3 审讯、黑暗潜入等）。
- 同样可接收 KP 推送的系统消息。

### 7. 即时解锁
- 浏览器与服务器保持推送连接（实际用 SSE，不用 WebSocket：不需要改反向代理配置）。KP 点“开放”，入口一秒内出现；点“关闭”，入口立刻消失。
- 每个入口（游戏、扫描项、个人档案条目等）三种状态，可按人设置（2026-11-25 定）：**隐藏**（看不到）/ **锁定**（看到名字，点了显示“权限不足”，用于剧情上先让玩家知道有这个东西）/ **开放**（可以启动）。
- **不显示占位格**，避免玩家从“???”的数量推测后面还有几个游戏。锁定状态统一显示一个“权限不足”区域，不透露数量。
- 玩家正在游戏时 KP 关闭入口：统一为“本局结束后关闭”（2026-11-25 定，不做立即中断）。实现：游戏页面立刻打不开，已打开的页面 3 小时内仍可加载素材。
- **场景预设**：例如“10/25 拘留所”，一键开放黑暗潜入和骇入、关闭之前的入口、更新出勤表。

### 8. 世界观网站
- 登录后全部可看（KP 不放剧透内容）。
- 图文页面，KP 在后台编辑；图片上传后服务器自动压缩为 WebP，保证国内速度。
- 新页面带“新”标记，支持搜索，手机可看。

### 9. 个人档案（每位 PL 一页，仅本人和 KP 可见）
- **目标**：KP 写入，包括 HO 的秘密目标。可随剧情更新（划掉已完成、加入新目标）。
- **进度**：按模组日期排列的时间线（10/15 导入 → 10/16 搜查……）。小游戏结果自动加入，KP 可手动添加条目。
- **资料 / 证物**：小游戏结果自动存为证物（例如录像排序成功 → 恢复画面截图和时间；50 层隐藏资料 → 识别码 1310）。另有玩家自己的笔记区。
- **团录**：
  - KP 上传 QQ 导出的聊天记录，系统整理：发言人对应角色、按角色着色、场外发言（括号内）可折叠或去掉、骰子结果单独标出。
  - 可见范围按场次设置：个人导入 = 本人 + KP；双人导入 = 该搭档两人 + KP（HO1+HO2、HO3+HO4）；集体剧情 = 所有人。
  - 早期导入的记录可能导不出 txt，因此同时支持：直接粘贴文本、上传截图存档、KP 手写剧情摘要。
  - 之后每次跑团结束都可以上传。

### 10. KP 控制台
在设计计划第九章的基础上增加：
- 邀请码管理、角色卡审核与锁定。
- 解锁面板（按人、按入口）、场景预设。
- 在线状态：只显示是否在线（2026-11-25 定：不显示在哪个页面，避免玩家觉得被窥探）。
- 秘密情报推送：只发给指定 PL，显示为系统消息，带“已读”。
- **以玩家视角预览**：选一个 PL，查看其当前界面。
- 访客内网编辑（公告、出勤表、作者信息）。
- 个人档案编辑（目标、进度）、团录上传与可见范围设置。

### 11. 测试账号
- 平台第一步完成时建立，账号名和初始密码届时交给 KP，不写入仓库。
- 两个测试玩家：一个仿生人（HO2 身份）、一个人类（HO1 身份），两种界面都能测。
- 标记为“测试”，结果不进正式记录；控制台可一键重置其进度和证物。

### 12. 其他
- 数据库每天自动备份。
- 团结束后可切换“存档模式”：全部内容开放供回看。
- 设计计划中的断线兜底（离线结果码）保留。

### 13. 内容编辑原则（2026-11-25 定）
- 内容（世界观页面、图片、内网、个人档案、团录）和游戏里的文字、数值、图片，全部由 KP 在后台编辑，存在服务器数据目录，不走代码仓库，不需要 Claude。
- 需要改代码的只有：新游戏、新玩法、界面结构的大改动。外观（颜色、字体等）放进编辑器。
- 后台提供“导出全部内容”（页面 + 图片打包下载），KP 本地留备份。
- KP 的安排：平台全部做完后，再慢慢填世界观和游戏内容。开发顺序不变。

## 四、服务器负担

按 4 名 PL + KP + 少量访客估算：
- 内存：平台后端常驻约 50–100MB，启动命令限制内存上限 256MB。服务器 16G，与 SillyTavern 同时运行无压力。
- CPU：游戏在玩家浏览器运行，服务器只发文件和转发消息，平时接近 0。批量上传图片时压缩会占用几秒。
- 流量：每月预计不到 1GB，额度 20TB。
- 平台与 SillyTavern 为两个独立进程，端口、域名分开，互不影响。

## 五、技术方案

- 部署：在 1Panel 安装 Node.js 运行环境，OpenResty 把请求转给后端（KP 已同意，Claude 届时写操作说明）。
- 后端：Node.js，**不依赖第三方包**（服务器不用 `npm install`，Node 18 以上即可）。数据存为一个 JSON 文件 `platform/data/db.json`（原计划 SQLite，按玩家规模改为 JSON，部署更简单），每天自动备份，保留 14 天。实时推送用 SSE（第 2 步）。
- 整个网站由 OpenResty 反向代理到平台（127.0.0.1:3100），游戏文件和受保护图片由平台在确认权限后发送，无权限返回 404。
- 现有游戏不改玩法：从公开目录移到受保护目录，启动时由平台传入技能值和难度，结果（`lastResult`）回传服务器。
- 不使用境外 CDN，全部自托管。

## 六、开发顺序

1. **账号系统**：登录页、邀请码注册、KP 登录、角色卡审核、测试账号；游戏文件改为受保护，关闭旧公开地址。
2. **解锁系统 + KP 控制台基础版**：开放 / 关闭 / 场景预设 / 以玩家视角预览 / 秘密情报推送；入口改为控制台管理（自动列出服务器上 `games/` 里的游戏，名字由 KP 起），不再写死在 `entries.js`。
3. **两种 PL 界面**：仿生人 HUD、Windows 风格办公电脑；接入骇入 demo 和录像排序；观战。
4. **内容部分**：访客内网与作者信息、世界观网站与后台编辑、个人档案（目标、进度、证物、团录导入）、导出全部内容。
5. 接上设计计划剩余部分（多人同时操作的联机、编辑器）。

完成第 1、2 步后，新游戏即可放心部署。

## 七、进度

### 第 1 步 账号系统（2026-11-25 完成，已部署）
- 代码在仓库 `platform/`，部署步骤见 `platform/README.md`（1Panel 创建 Node.js 运行环境 + 网站反向代理）。
- KP 初始化：首次启动时平台日志打印初始化码，在 `/kp/setup` 设置密码和密令；完成后该页面 404。忘记密码用 `node platform/tools/reset-kp.js`。
- 邀请码格式 `VOID-XXXX-XXXX`，一次性，绑定 HO。
- 登录限流：同一 IP 或账号 10 分钟失败 5 次锁 15 分钟；KP 登录另有全局计数（20 次）。
- 测试账号 test-ho1（HO1 人类）、test-ho2（HO2 仿生人），在控制台点“重置测试账号”生成密码，密码只显示一次。
- 部署时的坑：1Panel 反向代理地址框只填 `127.0.0.1:3100`（协议另选）；Node 运行环境关闭“端口外部访问”；部署后清一次 Cloudflare 缓存。
- 终端页、访客内网目前是简单的占位样式，第 3、4 步替换。

### 第 2 步 即时解锁 + 控制台（2026-11-25 完成，已部署）
- 推送：`platform/lib/events.js`（SSE，25 秒心跳，响应头 `X-Accel-Buffering: no`）。删除账号或改密码时先推 `logout` 再断开，对方页面立刻回登录页。
- 入口：`lib/entries.js` 每分钟扫描 `games/`，新游戏默认“未命名程序”、对所有人隐藏；名字和说明存在 `db.entries`，KP 在控制台改。
- 场景预设：保存当前全部玩家的入口状态；应用前弹出确认，列出每个玩家会变成什么。
- 消息：发给勾选的玩家，弹窗点“确认”才关闭，有提示音和手机振动；离线的下次打开终端时弹出；KP 看已读/未读；删除消息玩家那边也删除。
- 预览视角：`/terminal?as=玩家id`，只读，不弹消息、不标已读，实时跟随变化。
- 系统状态：代码版本、运行时间、内存、数据大小、最近备份、Node 版本。
- 控制台里正在填写的表单（消息、入口名字、玩家编辑）不会被推送刷新覆盖。
- 自动测试：`tools/test/platform_test.py`，覆盖第 1、2 步全部流程。
- 部署后修正（2026-11-25）：KP 和玩家用不同 cookie（`void_kp` / `void_sid`），同一浏览器可同时登录 KP 和一个玩家；只有 KP 登录时登录页不跳转；测试账号密码不含易混字符，登录忽略密码前后空格。同一浏览器里 KP 身份优先，打开游戏不受解锁限制；要测玩家的访问限制，用无痕窗口。

### 第 3 步 两种 PL 界面（设计 2026-11-25 定；3a、3b 已完成、待部署）

**共同部分**
- 开机动画：登录后 2–3 秒，可点跳过，每次登录只播一次。仿生人端是机体自检，人类端是系统启动。
- 消息（第 2 步的秘密情报）：仿生人端显示为“接收到加密通讯”，人类端显示为新邮件，收件箱保留历史。确认、已读、提示音沿用第 2 步。
- 角色卡只读显示：人类端叫“职员档案”，仿生人端叫“机体参数”。
- 游戏入口的隐藏 / 锁定 / 开放沿用第 2 步。
- 手机：同一套界面缩成单列；办公电脑的窗口在手机上全屏。
- 特效开关：两种界面都有“简化特效”，卡顿时自动开启（同游戏的做法）。

**仿生人 HUD（两套）**
- HO2 新型机 BR800：冷色（青白），线条干净，动画流畅。
- HO4 旧型机：单色琥珀（KP 可在后台改成绿色），偶尔出现噪点和字符错位。频率低，不影响阅读。（2026-11-25 重做后改为：靠布局区分，颜色灰白或淡绿，见下方“HUD 重做”。）
- 区块：顶部状态条（型号、时间、连接状态）、搭档体征、扫描、程序（游戏入口）、通讯记录、机体参数。
- **搭档体征**（HO2 看 HO1，HO4 看 HO3）：
  - 按当前 HP / HP 上限换算伤情：满 = 无伤；50% 及以上 = 轻伤；1%–49% = 重伤；0 = 濒死。
  - 心率、血压、呼吸随伤情变化，带小幅随机波动；心电图滚动，速度跟心率走。
  - 不显示 HP 数字，只显示伤情和体征。
  - KP 可手动覆盖单项（例如紧张时心率 130），覆盖可一键清除。
  - 搭档未注册或未审核时显示“未连接”。
- **扫描**：
  - KP 在控制台预先写扫描条目：目标名、数据行（以后可加图）。每条按人设隐藏 / 开放，可放进场景预设。
  - 玩家点“扫描” → 1–2 秒扫描动画 → 列出当前已开放的条目，点开看详情。新开放的条目标“新”。
  - 闲时也能点：没有开放条目时，扫描显示搭档体征和一句环境描述（如“未检测到威胁”），描述从台词池里随机取，台词池 KP 可编辑。
  - 战斗中：玩家在 QQ 宣言“扫描”，KP 开放对应条目（或用场景预设提前开放）。敌人条目只写静态资料（型号、装甲、弱点提示），不显示实时 HP，KP 不用多维护一个数字。
  - HO1 心脏伏笔做成一条只对 HO2 的扫描条目，KP 决定何时开放。
- **界面故障**：控制台按钮，选目标玩家和效果：雪花错字（2 秒）、黑屏（3 秒），可附带一行文字（如“警告：检测到外部入侵”）。对人类端触发时显示为 Windows 风格蓝屏 3 秒。

**办公电脑（仿 Windows 10）**
- 系统名虚构，暂定“MPD OS”，KP 可改。
- 桌面 + 任务栏 + 开始菜单；窗口可拖动、最小化、最大化、关闭。
- 桌面图标：邮件、职员档案、程序文件夹（游戏入口）、内网（打开警察厅内网）、记事本、回收站。
- 记事本：玩家自己的笔记，存服务器，只有本人和 KP 能看；第 4 步个人档案的笔记区直接用它。
- 回收站：KP 可放文件进去（文字），按人隐藏 / 开放，用来放线索或闲时彩蛋。
- 手机上图标排成网格，窗口全屏，任务栏在底部。

**战斗轮和 HP 同步**
- 战斗、宣言、骰子仍在 QQ，不搬到网站。网站在战斗中只做两件事：仿生人扫描敌人、骇入类游戏。
- SAN 不上网站，由骰娘管理，HUD 不显示。
- 控制台新增“体征”面板：4 名玩家各一行，显示当前 HP / 上限，带 −1、−5、+1 按钮和数字框，点了立即同步到搭档 HUD。
- 不需要每次受伤都改：一轮或一场战斗结束后改一次即可。HUD 只显示伤情档，小误差看不出来。

**接入骇入和录像排序**
- 平台启动游戏时把该玩家角色卡的技能值传进去，游戏开始界面里的操作员和技能值改为只显示、不可改。骇入难度（1.3 / 1.4 / 1.6）由 KP 在入口设置里定。KP 从控制台打开游戏时仍可手动选。
- 正式一局结束后结果（`lastResult`）自动上传服务器；KP 控制台“结果”列表出现新结果并有提示音；玩家端显示“结果已上传”。
- 次数：每个入口默认 1 次正式局；之后玩家仍可打开，但标“练习”、结果不计。KP 可点“再给一次”。录像排序游戏内自带的“重来”算同一局。
- 断线：结果先存在浏览器，下次连上自动补传。
- 观战在 3d 做；多人同时操作的联机（潜行、拆弹等）仍留在第 5 步。

**观战（3d，2026-11-25 定）**
- 方式：操作者的浏览器每秒约 10 次把画面数据发给服务器，服务器经现有推送连接转给观战者，观战者浏览器用同一套画法画出来，只能看不能操作。延迟约 0.2–0.5 秒。不传视频，不做“只传操作再重算”。
- 骇入：观战者看到完整弹幕画面（数据压缩后发送）。录像排序：传操作（点开哪段、判了哪段、排到第几步），观战端同一界面跟着动。
- KP 开放游戏时勾选观战者，或选“全员观战”；没被勾选的人收不到任何通知。KP 控制台也能看。
- 观战窗口：仿生人 HUD 里显示为“数据链路：接入中”，办公电脑上是“远程监视”窗口。
- 剧透：观战者由 KP 决定；录像排序的恢复画面是否给观战者看可单独设置。
- 之后的新游戏都按同样方式支持观战。

**开发拆分**（每部分做完跑测试、推送、KP 部署确认）

**HUD 重做（2026-11-25，KP 看过样稿后定，待部署）**
- 起因：KP 觉得第一版 HUD 像后台管理页面、不够用心；琥珀色干扰阅读；线框人形和头像都有点吓人。最后定：两套布局完全不同，中间统一用心形，不做头像上传。
- **HO2 新型机**：圆形主视野居中（慢速旋转的刻度环、准星）。左弧是心率表（颜色随伤情），右弧是呼吸；中间是线条心形 + 心电波形 + 同心环，跟着心率跳，每跳一下扩一圈波纹，濒死时闪烁。下方是带网格的心电图（余辉渐隐）。左边扫描面板，右边程序、通讯、机体参数，面板用细线连到主视野。背景是很淡的六角网格和下落的十六进制数据流（约 12 帧/秒）。
- **HO4 旧型机**：老式终端布局，没有圆形视野。左上“搭档监视”：像素心形（跟心率闪，重伤缺一行、濒死缺两行）+ 读数表（`[|||||.....]` 文字条）+ 示波器心电图；左下“扫描记录”命令行；右边程序（带编号）、通讯记录、机体参数（文字条）。底部功能键条 F1 扫描、F2–F4 跳到对应区块，键盘 F1–F4 也可用。颜色灰白（默认）或淡绿，控制台切换（数据里 `hudColor` 为 grey / green，早期的 amber 自动改成 grey）。每 8–20 秒字符错位一次，每 15–35 秒整行闪一下。
- 扫描：HO2 主视野里雷达转动，每个已开放条目出现一个锁定框（位置由条目 id 决定），结果逐行显示，标题前有十六进制“解码”行；HO4 显示命令行和进度条，结果按编号列出。扫描进行中，上一次的结果保留到新结果出来。
- 加密通讯：正文先是乱码，约 1 秒内逐字解码（简化特效时 0.3 秒），解码完“确认”才能点。
- 机体参数：加“机体完整度”（本机 HP / 上限）；HO2 技能是能量条，HO4 是文字条。
- 开机：HO2 六边形徽记逐笔画出 + 每行带进度条；HO4 像老电脑开机自检的文字。
- 简化特效（手动或卡顿自动）：关掉背景数据流、刻度环旋转、心形波纹、扫描线、逐行出现、旧型机的错位和闪行；心电图隔帧画。
